02

What it is

A self-hosted RAG workbench. Upload documents into knowledge bases, ask questions in chat, and change how the answer is retrieved — per question, per document, per provider.

Switch modes mid-conversation

Six retrieval strategies in a picker. Re-ask the same question under another mode and compare the citations.

Tune indexing per document

Character, sentence, paragraph or page chunking — with size and overlap — set on each upload, not per install.

Bring any LLM — or none

Eleven providers behind one picker, from Groq's free tier to a fully local Ollama. With no key at all, answers are extractive and still cited.

Audit every answer

Citations carry page and character spans. Open one and the source PDF renders with the passage highlighted.

The six modes

Contextual Hybrid

Matches your wording against each passage and the context around it. The default.

See how it works

How it works

  1. Score every passageEach passage is scored on how many of your words it contains, over the passage plus a six-line header naming its document, file and position — so a passage about “notice” in a contract about termination scores higher than the same words in an unrelated file.
  2. Normalise for lengthThe score is divided by passage length, so a long passage cannot win just by containing more words.
  3. Keep the top fiveThe five best passages become the evidence, and the answer is written from those alone.

When to use it

Use it for almost everything. It is the fastest mode and the one every other mode builds on. It is also what runs if a mode name is not recognised.

Fastest · one pass over your documents

RAG-Fusion

Searches several rephrasings of your question and merges the rankings.

See how it works

How it works

  1. Rewrite the question, mechanicallyUp to four versions are built by rule, not by a model: your question as typed, its meaningful words with duplicates removed, those words reversed, and the first three of them.
  2. Search with each oneEvery version runs a full Contextual Hybrid search of its own, eight passages deep.
  3. Merge by rank, not by scoreA passage earns 1/(60 + its rank) from every version that found it, and the totals decide the winner — so a passage several rephrasings agree on beats one that a single phrasing loved.

When to use it

Use it when your wording might not match the document’s. It costs one search per rephrasing, so it is slower than the default.

Slower · four searches merged

GraphRAG

Boosts passages naming the same parts, people or terms as your question.

See how it works

How it works

  1. Match your words to named thingsDuring indexing, recurring names — parts, people, terms — were extracted from your documents. Any of your words that matches one of those names is a signal.
  2. Lift the passages that mention themEvery passage that names a matched thing gets a bonus, and the bonus is capped as a fraction of the best ordinary score — so it can reorder the results but never overwhelm them.
  3. Pull in what keywords missedA passage found only through a shared name can still enter the results, which is how this mode surfaces evidence a plain keyword search walks past.

When to use it

Use it for questions about how things relate — a part, a clause or a person appearing in several places. It does not walk a graph of relationships; it re-ranks on shared names.

Moderate · one search plus a capped re-rank

Corrective

Grades the evidence first, and declines rather than answer on weak support.

See how it works

How it works

  1. Search once, then gradeA normal Contextual Hybrid search runs, and the result is measured: how much of your question the passages actually cover, and whether anything scored above zero.
  2. Retry differently if it is thinIf the evidence does not clear the bar, the question is re-run as a RAG-Fusion search — a second attempt with different phrasings rather than the same one again.
  3. Refuse if it is still thinIf that also fails, you are told so, and told which of your words matched nothing — so a typo is distinguishable from a topic your documents do not cover.

When to use it

Use it when a wrong answer would cost more than no answer. Every mode refuses on weak evidence; this is the one that tries a second route before giving up.

Moderate · one search, sometimes two

Multi-Modal

Favours tables, spreadsheets and media when the question calls for them.

See how it works

How it works

  1. Read the intent in your wordsWords like table, row, total, chart or transcript say what kind of content you are after.
  2. Weight the matching kindPassages recorded as that kind of content are scored 1.8x; ordinary document text gets 1.1x. Nothing is excluded — the ordering changes, not the pool.
  3. Score as usualEverything else is the same term-overlap scoring the default mode uses.

When to use it

Use it for “what was the total in the summary table”. If your question names no content type, it behaves almost exactly like the default.

Fast · one pass with a modality weighting

Agentic RAG

Runs the other modes together and combines their best results. Slowest.

See how it works

How it works

  1. Choose the tools by keywordFive retrieval tools get fixed weights, adjusted by rule: words like compare or between raise GraphRAG’s weight, words like table or chart raise Multi-Modal’s. No language model plans anything here — it is a keyword test.
  2. Run them all and mergeEach tool runs and its scores are normalised, weighted, and given a rank bonus, so tools with different scoring scales can be compared at all.
  3. Repair, then gradeIf the merged evidence is still thin, extra passes run over the rephrasings, and the final evidence is graded and reported with the answer.

When to use it

Use it when an answer matters more than latency: it does the work of four or five modes for one question, and returns up to seven passages instead of five.

Slowest · five tools plus repair passes
03

Why it exists

Trying two RAG designs normally means building two RAG systems.

Each variant wants its own chunker, retriever, provider SDK and glue — so most teams build one pipeline, ship it, and never learn what a different design would have answered. Nexarag collapses the comparison into configuration: modes are a dropdown, chunking is an upload setting, providers are a picker. The difference between two RAG designs becomes an experiment, not a quarter.

Grounded enough to refuse. Every mode passes an evidence gate before answering. When retrieval finds nothing, Nexarag says so — and names the words that matched nothing, so a typo is distinguishable from a genuinely uncovered topic. No provider key, no answer invented: the model writes prose only over passages retrieval actually returned.

Local by default. The stack runs on your machine under Docker. The lexical baseline needs no model and no network; embeddings are opt-in per document; provider keys are encrypted at rest. Pick Ollama and nothing leaves the box at all.

04

How it works

Three services in one Compose file: a React SPA behind nginx, a FastAPI backend that owns retrieval, and MySQL holding everything — chunks, terms, vectors, graph, jobs and history.

Architecture

The diagram builds as you scroll, in the order a question actually travels. Hover any box to trace one hop out from it.

Data flow

  1. 1

    Ingest

    Upload returns 202 in under a second; a background job does the work — text extraction (PDF, DOCX, XLSX), chunking with that document's own strategy and size, optional embeddings, and an entity graph. The tasks screen polls live progress; cancel works mid-document.

  2. 2

    Retrieve

    Your question hits the mode you picked. All six score the same chunk set — lexical term overlap by default, fused with cosine similarity where a document was embedded. An evidence gate decides whether the passages actually support an answer; if not, Nexarag declines and names the vocabulary that missed.

  3. 3

    Synthesize

    With a provider configured, the model writes the answer over the retrieved passages and the reply streams into the chat. Without one, you get the deterministic extractive answer. Either way the citations resolved before the first byte.

  4. 4

    Inspect

    Each citation opens the evidence panel: the source PDF page renders with the passage highlighted, matched client-side. A position the system doesn't know is reported as unknown — never guessed.

05

Quick start

One command from a clean machine. Prerequisites: Docker 24+ with Compose v2, and ~4 GB free.

Run it

bash
git clone https://github.com/shakthivel-rc/Nexarag-api.git
cd Nexarag-api
make setup      # clones the SPA beside it, writes .env, builds, starts

# Web UI  →  http://localhost:8080
# API     →  http://localhost:8000/api/v1/health/ready

Sign in as superadmin@nexarag.local with the generated SUPERADMIN_PASSWORD in .env. make on its own lists every other task — logs, shells, tests, teardown.

First question

  1. Create a knowledge base and upload a PDF. Chunking strategy, size and embeddings are set per document on the upload form.
  2. Watch it index on the tasks screen — per-document progress, honest outcomes, cancellable.
  3. Ask a question in chat. Then switch the retrieval mode in the context bar and ask again.
  4. Open a citation. The page renders with the passage highlighted — that's the evidence the answer stood on.

No API key? Everything still works.

Without a provider, answers are extractive — the retrieved passages themselves, cited. Add a key later in chat setup; Groq's free tier is the recommended first provider.

Local models (optional)

For a fully local setup, install Ollama and pull one model for chat, one for embeddings:

bash
ollama pull llama3.1:8b        # chat
ollama pull nomic-embed-text   # per-document embeddings

Select Ollama in the chat provider picker, and choose an embedding model on the upload form for any document you want semantic matching on. One networking note: from inside the Docker stack, localhost:11434 is the container, not your machine — set the provider's base URL to an address the container can reach (and let Ollama listen on it with OLLAMA_HOST=0.0.0.0). A native make setup-native run needs no change. Embeddings are off by default — enabling them is a per-document decision, because it sends that document's text to whichever provider you chose.

06

Tech stack

Deliberately boring infrastructure: no broker, no vector database, no vendor SDKs — and a test suite standing behind every layer.

Backend

FastAPI + SQLAlchemy 2

55+ endpoints; explicit sessions, controller-owned transactions

MySQL 8 + Alembic

Chunks, term index, vectors, entity graph, jobs — one store

pypdf + stdlib zipfile

PDF via pypdf; DOCX and XLSX via the stdlib — nothing heavier

PyJWT + bcrypt

Sessions, refresh rotation, role-based permissions

LLM layer

11 providers, 4 wire protocols

OpenAI, Anthropic, Gemini, Groq, Ollama, OpenRouter, Mistral, Cerebras, Cloudflare, SambaNova, Z.ai

stdlib urllib only

One HTTP seam, retry with backoff, streamed replies — no SDKs

Fernet encryption

Provider keys encrypted at rest, returned only masked

4 embedding providers

Ollama, OpenAI, Gemini, Mistral — chosen per document

Frontend

React 19 + Vite

Route-split SPA; Redux Toolkit state; typed API client

Tailwind v4 + shadcn/ui

Token-driven theming — ten themes, light and dark

pdf.js lazy

Evidence panel renders cited pages with client-side highlights

WebSocket chat

Typed frames — stage, citations, deltas — with HTTP fallback

Infrastructure & testing

Docker Compose

MySQL + API + SPA-behind-nginx; make setup from zero

No broker, by design

Background indexing via a jobs table and conditional claims

850+ backend tests

pytest — hermetic by default, plus a live-stack suite
